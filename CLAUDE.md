# xeibe

Rust library for reading GML files and WFS responses into Arrow/GeoArrow. It
is still a design-phase skeleton: most function bodies are `todo!()`. The
design docs in `docs/` are the source of truth, starting with `docs/README.md`
and `docs/architecture.md`. `docs/support-matrix.md` tracks status. After
changing a status there, rerun `scripts/support_summary.py`. Draw diagrams in
docs as Mermaid (```` ```mermaid ````), not ASCII art.

Naming: the project is `xeibe`. The crates are `xeibe-*`, and the CLI binary
and the Python module are both `xeibe`. GML, the format, keeps its own name,
e.g. `read_gml()`, `.gml` inputs and the GML namespaces. The project was once
the `gmltemp` workspace with crates named `gml-*`, and older notes may still
use those names.

## Layout

| Path | Contents | In git |
|---|---|---|
| `crates/xeibe-*` | Workspace crates: core, geom, schema, arrow, io, wfs, datafusion, cli (binary `xeibe`), py (Python module `xeibe`) | yes |
| `docs/` | Design docs | yes |
| `tests/data/` | Small curated samples, `samples.toml`, generated `samples.json`/`BOM.md`; see `tests/data/README.md` | yes |
| `scripts/` | Tooling (see below) | yes |
| `ogc_schemas/` | Mirror of schemas.opengis.net plus OGC spec PDFs (~120 MB) | no, run `scripts/fetch_ogc_schemas.py` |
| `schemas-extra/` | For offline validation: `catalog.xml` (schemas.opengis.net → `ogc_schemas/`), W3C xlink/xml schemas, unzipped OGC xlink 1.0.0 | no, generated by `scripts/fetch_ogc_schemas.py` |
| `example_data/` | Raw test corpus (~22 GB). Only `SOURCES.md` (provenance) and `wfs/endpoints-*.txt` are tracked | no |

## Setting up a new environment

System tools:

- Rust stable with edition 2024 (MSRV 1.85). Developed on 1.97.
- `uv`. All Python scripts are PEP 723 scripts with the shebang
  `#!/usr/bin/env -S uv run --script`, so you run them directly
  (`scripts/foo.py`) and uv installs their dependencies. There is no venv or
  requirements file. They need Python 3.11 or newer.
- Docker. `scripts/gdal` runs GDAL from `ghcr.io/osgeo/gdal:ubuntu-full-3.13.3`.
  The system GDAL is never used.
- `xmllint` (Debian/Ubuntu package `libxml2-utils`), for `scripts/validate-gml`.

Steps, from the repo root:

```sh
cargo check --workspace --all-targets     # default members skip xeibe-datafusion/xeibe-py; --workspace includes them
scripts/fetch_ogc_schemas.py              # ogc_schemas/ (SCHEMAS_OPENGIS_NET.zip + spec PDFs, ~70 MB) and schemas-extra/
docker pull ghcr.io/osgeo/gdal:ubuntu-full-3.13.3   # optional; scripts/gdal pulls on first use
```

You only need the test corpus to rebuild `tests/data/`. The committed samples
are enough to build and test the crates.

```sh
scripts/corpus/fetch_gdal_autotest.sh     # example_data/gdal-autotest-src (sparse GDAL clone, pinned commit)
scripts/corpus/reference_data.py          # example_data/reference/: PRG + Natural Earth boundaries (~390 MB), builds axis_reference.gpkg via GDAL
scripts/corpus/inventory_eu.py            # example_data/_inventory/: portal inventories (metadata only)
scripts/corpus/inventory_pl.py
scripts/corpus/downloads.py select        # example_data/_inventory/selection.jsonl
scripts/corpus/downloads.py download      # example_data/downloads/: selected GML/ZIP files (up to 18 GB)
for l in geoportal-pl eu; do              # example_data/wfs/: capabilities + small GetFeature responses
  scripts/corpus/fetch_capabilities.py example_data/wfs/endpoints-$l.txt 16
  scripts/corpus/fetch_wfs_samples.py example_data/wfs/endpoints-$l.summary.json
done
scripts/corpus/axis_survey.py > example_data/wfs/axis_survey.txt
scripts/corpus/analyze.py                 # example_data/_inventory/corpus_analysis.jsonl
```

The two endpoint lists, `example_data/wfs/endpoints-*.txt`, are tracked in git.
They were compiled once, from the geoportal.gov.pl service pages and from the
data.europa.eu inventory (one endpoint per host). The downloads, WFS and
inventory scripts read live portals and services, so a rerun won't match the
original corpus exactly. `example_data/SOURCES.md` records
the dates and licences of the original.

Some data was downloaded by hand (see `SOURCES.md`) and has no script. These
are GUGiK open data from opendata.geoportal.gov.pl. The URLs below are likely
sources, but their contents haven't been checked against the local copies:

- `example_data/PRG-punkty_adresowe_2026-08-10/`: PRG address points, the
  mazowieckie and lubelskie exports. Whole country:
  `https://opendata.geoportal.gov.pl/prg/adresy/PunktyAdresowe/POLSKA.zip`.
- `example_data/A00_Granice_panstwa.gml`, `A01_Granice_wojewodztw.gml`: PRG
  boundaries, from
  `https://opendata.geoportal.gov.pl/prg/granice/00_jednostki_administracyjne_gml.zip`.
- `example_data/0808_GML/`: BDOT10k for powiat 0808, from
  `https://opendata.geoportal.gov.pl/bdot10k/schemat2021/08/0808_GML.zip`.

## Scripts

- `scripts/gdal <cmd>` runs GDAL in the pinned Docker image. The container keeps
  running and is reused. `example_data/`, `ogc_schemas/` and `tests/data/` are
  mounted read-only, so write outputs under `target/`.
- `scripts/validate-gml FILE...` validates offline through
  `schemas-extra/catalog.xml`. Add `--net` for remote application schemas.
- `scripts/schema_coverage.py` lists GML/WFS schema elements that aren't in the
  support matrix. `scripts/support_summary.py` regenerates the summary table in
  the matrix.
- `scripts/corpus/build_samples.py` rebuilds `tests/data/samples/**`,
  `samples.json` and `BOM.md` from `samples.toml`. It needs `example_data/`,
  Docker and `reference_data.py` to have run.
- `scripts/corpus/axis_evidence.py` is the exception to the uv rule. It runs
  inside the GDAL container (`scripts/gdal python3 scripts/corpus/axis_evidence.py`),
  because it needs `osgeo`.

When adding a Python script, give it a PEP 723 block that declares its
dependencies, use the uv shebang and make it executable. Record any new download
in `example_data/SOURCES.md`, and prefer a script over a manual download.
