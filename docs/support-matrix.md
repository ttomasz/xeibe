# Support matrix

This file tracks which parts of GML and WFS the project supports, plans to support,
or leaves out on purpose. Most of it is not implemented yet. Update the status here in
the same PR that implements a feature.

## Legend

| Status | Meaning |
|---|---|
| ✅ Supported | Implemented and tested (link the test in *Notes*) |
| 🚧 In progress | Being implemented |
| 📋 Planned | Will be supported |
| 🤔 Considering | Undecided. Needs a use case or a design decision |
| ❌ Not planned | Out of scope on purpose (reason in *Notes*) |

| Priority | Meaning |
|---|---|
| **P0** | MVP: needed to convert the test corpus (PRG, BDOT10k, simple WFS 2.0) |
| **P1** | Next: needed for common real-world data |
| **P2** | Later: nice to have or rare in practice |
| — | Not applicable (not planned) |

Versions column: **2** = GML 2.1.x, **3.1** = GML 3.1.1 (and 3.0), **3.2** = GML 3.2.1/3.2.2.

**Coverage check:** every global element and attribute in the schemas under
`ogc_schemas/` (GML 2.1.2, 3.1.1, 3.2.1; WFS 1.0.0, 1.1.0, 2.0) is either listed here
by name or belongs to a group row, such as coverages, topology or CRS dictionaries.
`python3 scripts/schema_coverage.py` lists schema names that don't appear in this
file. Not listed individually:
- abstract elements (`AbstractCurve`, `_Geometry`, …);
- the internals of CRS/datum/coordinate-operation definitions;
- elements that exist only in XSD annotations (`targetElement`,
  `reversePropertyName`, `associationName`, `defaultCodeSpace`, `gmlProfileSchema`).
